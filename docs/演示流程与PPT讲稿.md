# 智融反诈项目演示流程与 PPT 讲稿

## 1. 演示目标

演示时不要逐个介绍页面，而是围绕一个真实诈骗场景讲清楚系统价值：

> 用户收到可疑微信消息，系统自动捕获并分析风险，随后提醒用户和监护人，最终在系统中形成预警和报告。

推荐演示主线：

```text
诈骗消息进入微信
→ wxauto 自动监听
→ 后端 AI 风险分析
→ 判断中/高风险
→ 弹窗或微信提醒
→ Web/小程序查看预警、报告、知识库
```

## 2. 演示前准备

### 2.1 环境准备

- 打开 Windows 桌面微信，并登录用于演示的微信账号。
- 启动后端服务：

```bat
run-model.bat
```

- 启动 Web 前端：

```bat
run-all-model.bat
```

或确认前端已运行在：

```text
http://127.0.0.1:8008
```

- 准备另一个微信号，用来给当前演示账号发送诈骗测试消息。
- 准备备用演示视频，防止现场网络、微信或模型接口不稳定。

### 2.2 推荐测试文本

建议提前准备几条稳定触发风险的文本：

```text
你的银行卡账户涉嫌洗钱，请立即把资金转入安全账户，并提供短信验证码配合核查。
```

```text
我是平台客服，你的贷款额度已冻结，需要先缴纳保证金才能解冻，否则会影响征信。
```

```text
我是公安局工作人员，你涉嫌一起资金案件，请不要告诉任何人，马上添加微信处理。
```

### 2.3 现场注意事项

- 演示账号不要暴露真实隐私。
- 微信联系人名称、测试消息、API Key 等敏感信息提前处理。
- 浏览器提前打开 Web 页面。
- 后端、前端、微信脚本都提前试跑一遍。
- 如果模型响应较慢，主持人可以同步讲解系统架构，避免冷场。

## 3. PPT 结构建议

### 第 1 页：项目标题

标题：

> 智融反诈：多模态智能反诈预警与监护人联动系统

讲稿：

大家好，我们的项目是智融反诈，一个面向老年人、学生等易受骗群体的智能反诈辅助系统。它不仅能识别诈骗文本，还能接入微信聊天场景，实现实时风险提醒，并通过监护人机制帮助家属及时介入。

### 第 2 页：背景与痛点

页面要点：

- 诈骗场景越来越多样化。
- 诈骗信息常出现在微信、短信、语音、视频等日常场景。
- 老年人、学生等群体识别能力不足。
- 很多反诈提醒发生在被骗之后，干预不够及时。

讲稿：

现在很多诈骗并不是发生在一个专门的诈骗 App 里，而是发生在用户日常使用的微信、电话、图片、音视频中。传统反诈产品更多偏知识宣传，用户需要主动查询。我们希望把风险提醒提前到诈骗信息刚出现的时候。

### 第 3 页：项目方案

页面要点：

- 多模态诈骗识别。
- 微信实时消息监听。
- 监护人联动提醒。
- 风险报告与知识库闭环。

讲稿：

我们的方案由四部分组成：第一，多模态检测，支持文本、图片、音频、视频；第二，通过 wxauto 监听桌面微信消息；第三，检测到中高风险后提醒用户和监护人；第四，把风险记录沉淀为预警、通知和安全报告，形成完整闭环。

### 第 4 页：系统架构

页面建议画成：

```text
微信 / Web / 小程序
        ↓
前端交互层
        ↓
Node.js 后端 API
        ↓
AI 模型分析服务
        ↓
风险事件 / 通知 / 报告 / 知识库
```

讲稿：

系统分为前端交互层、后端服务层、AI 分析层和数据存储层。用户可以通过 Web 或小程序主动检测，也可以通过 wxauto 监听微信消息。后端统一调用 AI 模型分析，并将结果写入风险事件、通知和报告。

### 第 5 页：核心功能

页面要点：

- 文本诈骗检测。
- 图片、音频、视频检测。
- AI 反诈助手。
- 预警中心。
- 监护人管理。
- 安全报告。
- 反诈知识库。

讲稿：

这是系统的核心功能。用户既可以主动上传内容检测，也可以在聊天中被动接收预警。监护人可以查看绑定用户的风险情况，安全报告可以帮助用户回看风险事件，知识库用于补充反诈教育。

### 第 6 页：演示流程

页面要点：

```text
主动检测 → 微信实时预警 → 监护人查看 → 报告留痕
```

讲稿：

接下来我们用一个完整场景来演示。假设用户收到一条冒充公安的诈骗消息，系统会识别其中的“涉嫌案件”“安全账户”“验证码”等风险点，并及时提醒用户和监护人。

### 第 7 页：创新点

页面要点：

- 从宣传型反诈转向场景型预警。
- 多模态识别覆盖更多诈骗载体。
- wxauto 接入真实聊天环境。
- 监护人机制适配弱势群体保护。
- 风险检测到报告留痕形成闭环。

讲稿：

我们的创新点主要体现在场景接入和闭环设计上。系统不是只做一个知识展示页面，而是尝试接入真实聊天环境，在风险发生过程中给出提醒，并让监护人能够及时介入。

### 第 8 页：未来展望

页面要点：

- 优化模型识别准确率。
- 加入用户反馈和误报处理。
- 强化隐私保护和权限体系。
- 替换为更合规的消息接入方式。
- 建立诈骗案例库和风险趋势分析。

讲稿：

后续我们会继续优化模型识别效果，加入用户反馈机制，并强化数据安全。当前 wxauto 更适合作为比赛原型验证，未来可以替换为企业微信接口、移动端授权检测或其他更合规的接入方式。

## 4. 现场演示步骤

### 步骤一：展示 Web 首页或检测页

操作：

- 打开 `http://127.0.0.1:8008`。
- 进入反诈检测页面。
- 输入准备好的诈骗文本。
- 点击检测。

讲解：

这里我们先演示用户主动检测。系统会把文本提交给后端 AI 分析接口，返回风险等级、置信度、风险原因和处理建议。

预期效果：

- 页面显示中风险或高风险。
- 展示风险原因，例如“冒充公检法”“要求转账”“索要验证码”。
- 展示处理建议，例如“不要转账”“不要提供验证码”“拨打官方电话核实”。

### 步骤二：展示多模态能力

操作：

- 简要展示图片、音频、视频上传入口。
- 不一定每个都现场跑完整流程，避免耗时。

讲解：

真实诈骗不只通过文字发生，所以系统支持多模态检测。图片可能包含钓鱼二维码，语音可能冒充客服或熟人，视频可能传播诈骗素材。后端会统一把分析结果结构化为风险等级和建议。

### 步骤三：展示 wxauto 微信实时预警

操作：

- 确认后端已启动。
- 运行：

```bat
run-wechat-demo.bat
```

- 使用另一个微信号向演示账号发送可疑消息。
- 等待桌面弹窗或微信提醒。

讲解：

现在演示系统的实时预警能力。桌面微信收到消息后，wxauto 脚本会自动捕获新消息，并调用后端 AI 分析接口。如果风险达到阈值，系统会自动发出提醒。

预期效果：

- 命令行显示监听到微信消息。
- 命令行显示 AI 分析风险等级。
- 桌面出现风险提醒。
- 指定联系人收到反诈提醒消息。

### 步骤四：展示监护人管理和预警中心

操作：

- 切换到 Web 或小程序页面。
- 打开监护人管理。
- 展示绑定关系。
- 打开预警中心或通知列表。

讲解：

对于老年人、学生等人群，单靠本人判断可能不够，所以系统支持监护人绑定。检测到风险后，监护人可以及时收到提醒，帮助被监护人核实和止损。

### 步骤五：展示安全报告和知识库

操作：

- 打开安全报告页面。
- 展示报告列表或报告详情。
- 打开知识库页面。

讲解：

系统会把风险事件沉淀为报告，用户可以事后复盘。同时，知识库提供常见诈骗类型和防范建议，帮助用户提升长期反诈意识。

## 5. 备用演示方案

如果现场模型接口不稳定：

- 使用提前录制的视频展示完整流程。
- 使用已保存的报告和通知数据展示结果。
- 现场重点讲架构、流程和价值。

如果微信自动化失败：

- 直接演示文本检测接口。
- 说明 wxauto 是桌面微信原型接入方案。
- 使用截图或视频展示成功效果。

如果前端启动失败：

- 使用 `test-api.html` 或接口测试方式演示后端。
- 展示数据文件中的报告、通知、风险事件。

## 6. 三分钟演示讲稿

大家好，下面演示我们的智融反诈系统。首先我们进入反诈检测页面，输入一条典型诈骗话术：“你的银行卡涉嫌洗钱，请立即转入安全账户并提供验证码”。系统会调用后端 AI 模型进行分析，可以看到结果中给出了风险等级、置信度、风险原因和处理建议。

接下来展示实时聊天场景。我们打开桌面微信，并启动 wxauto 监听脚本。现在用另一个微信号给演示账号发送一条可疑消息。系统捕获消息后，会自动提交到后端分析。如果判断为中高风险，就会弹出桌面提醒，并向指定联系人发送反诈预警。

最后我们回到 Web 端，可以看到预警中心、安全报告和知识库。风险事件会被记录下来，方便用户和监护人事后查看。通过这个流程，系统形成了从风险发现、AI 分析、及时提醒到报告留痕的完整闭环。

## 7. 一句话收尾

我们的项目希望把反诈能力从“用户被骗后学习”提前到“诈骗信息出现时提醒”，用多模态识别、微信场景接入和监护人联动，帮助用户更早发现风险、更快做出正确判断。
